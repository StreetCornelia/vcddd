## 作用

蓝图、汇报稿、评审材料和其他报告是当前事实的阅读视图，不是固定 VCDDD 产物，也不是创建业务或设计事实的地方。

## 启动条件

只有用户明确要求报告时调用。使用用户给出的：

- 目标读者和目的；
- 关注范围；
- 结构或示例；
- 文件格式；
- 保存位置。

缺少输出位置且任务确实需要写文件时，通过主控询问；不要默认创建 `reports/` 或固定蓝图文件。

## 允许与禁止

报告语言服从 [业务语言与建模边界](language-and-modeling.md)。面向非开发人员时只使用用户词汇和普通话；Domain 报告可以使用 DDD 术语，但必须同时保留可追溯的普通话业务含义。报告不能用行业黑话压缩或改写事实。

允许：

- 摘取、合并、压缩和调整顺序；
- 统一术语；
- 从已有关系绘制结构图、流程图和时序图；
- 链接或嵌入已有原型、截图和验证结果；
- 为目标读者改写表达，但不改变语义。

禁止：

- 新增没有来源的业务目标、系统或责任；
- 临时发明 Domain、架构、模块、API、核心接口内部编排、表和字段；
- 根据代码或表名猜测理想设计；
- 把原型临时实现提升为事实；
- 为让报告完整而隐藏缺失来源；
- 在报告中修复源文档问题。

Domain 之后的源文档已有权威图时，报告优先链接、嵌入或按目标读者摘取这些图，不重新推断结构。为报告简化图时标明来源和省略范围，简化图仍是派生投影，不能与 [设计图表达协议](diagramming.md) 规定的权威图竞争。

## 生成流程

1. 根据用户结构列出每个报告章节需要的事实；
2. 为每项事实定位当前权威文档和章节；
3. 检查竞争版本、失效状态和适用范围；
4. 只从当前来源摘取和组织；
5. 在任务记录和报告交付记录中维护章节到来源的映射；
6. 写入用户指定位置；
7. 把使用的来源、未覆盖内容和报告适用范围写入完整任务，把报告路径和下一步写入 `主控状态.md`。

不要为了追溯而污染面向读者的报告正文。除非用户、报告模板或项目规范明确要求，不在每个章节重复来源，也不强制在报告开头增加来源清单。完整任务中使用：

```text
文档性质：派生报告
适用范围：
来源文档：
来源版本或生成时点：
```

用户要求检查是否像人话，或报告引入大量新压缩表达时，按 [语言验证 Agent](language-validation-agent.md) 盲测目标读者实际看到的片段。报告 Agent 根据结果修改表达，语言验证 Agent 不改报告事实。

报告 Agent 把这组信息保存在当前任务或报告交付记录中；主控不从聊天回执重新抄写。报告更新时根据记录重新定位并读取权威来源，不直接沿用旧报告内容；来源记录失效时重新建立映射。

## 来源不足

无法从现有文档生成某部分时停止该部分并返回：

```text
缺失事实：
需要它的报告章节：
应修改的源文档：
负责角色：
当前可以生成的部分：
```

事实拥有者补齐后再重新投影。报告 Agent 不替事实拥有者思考并写入缺口。
