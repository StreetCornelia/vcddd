## 目标

依据当前开发基线实现可观察业务结果，并用代码、迁移、测试和运行结果形成新的现实证据。开发 Agent 不重新定义业务或设计事实。

## 进入开发

读取：

1. 当前任务；
2. `systems/<系统>/开发基线.md`；
3. 本切片直接引用的系统拆分、模块拆分、API 和数据库章节；
4. 仓库规范、代码和测试。

开发基线必须为 `当前`，本切片必须落入其适用范围。否则返回主控，请求系统与开发设计 Agent 补充或重新生成。

## 纵向实现

按用户或上游可观察结果组织：

```text
业务线结果
→ API
→ 模块与应用用例
→ Domain 行为
→ 数据和外部 Adapter
→ 代码
→ 测试和运行结果
```

每个切片明确：

- 服务的业务目标和业务线；
- 进入条件、正常结果和不可接受结果；
- API、模块和 Domain；
- 状态、数据和外部事实变化；
- 并发、幂等、超时、取消和恢复；
- 必要测试组合；
- 完成定义和观察证据。

依赖先于引用者，但实现顺序服从当前切片。不要用没有真实业务结果的技术骨架冒充端到端完成。

## 发现设计问题

返回主控而不是直接修改设计：

- 业务结果错误：请求业务设计 Agent；
- Domain 对象、行为或规则矛盾：请求系统与开发设计 Agent 修改系统拆分；
- 模块责任或依赖不可实现：请求修改模块拆分；
- API 无法表达结果：请求修改 API 设计；
- 数据约束无法保持不变量：请求修改数据库设计；
- 平台能力不成立：请求技术验证；
- 只是实现缺陷：自行修复。

报告包含问题位置、运行或代码证据、影响范围和当前切片是否可继续。

## 验证与回写

按风险组合：

- Domain 单元测试；
- 模块与应用集成测试；
- API 契约测试；
- Repository 与数据库测试；
- 端到端和人工操作；
- 真实运行、容量和故障验证。

完成后返回：

- 代码、迁移和测试路径；
- 实际运行结果；
- 与开发基线的偏差；
- 新发现的设计问题；
- 已实现切片和剩余风险；
- 应由主控更新的任务与系统导航。
