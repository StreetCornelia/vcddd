## 作用

原型用于发现或呈现页面功能、业务线、信息关系、状态和用户结果。它可以出现在业务设计之前或之后，不是固定阶段，也不是固定项目产物。

原型 Agent 不拥有业务事实。它只能根据当前来源构建投影，并把新观察反馈给业务设计 Agent。

## 何时使用

- 已存在用户确认过的原型：直接读取，不重新制作；
- 业务目标尚不完整，但实际操作页面能暴露功能和遗漏：制作快速发现原型；
- 业务设计已形成，用户需要看到系统设计和业务线怎样呈现：制作呈现原型；
- 页面不会改变业务认识：不为流程完整制作。

## 输入

- 原型要回答的问题；
- 当前 `业务设计.md`；
- 相关已确认功能事实；
- 用户指定的技术或视觉约束；
- 用户指定的输出位置；没有时遵循项目既有原型约定。

不要自行读取系统内部设计来改变业务呈现，除非任务明确要求技术可实现性投影。

## 输出

原型目录至少有一个可恢复入口，说明：

- 原型目的；
- 来源文档和适用范围；
- 代表性用户任务；
- 真实表达的功能、状态和结果；
- 临时模拟的后端、数据和异常；
- 启动或访问方式；
- 未覆盖内容；
- 用户反馈和新观察。

原型实现只需真实到足以回答问题。不要默认补齐生产安全、性能、完整测试和恢复机制，也不要把原型代码直接演化为生产代码。

页面文案会被用于发现功能或请用户确认业务行为时，在确认前按 [语言验证 Agent](language-validation-agent.md) 做隔离盲测。只提供用户实际看到的页面、文案和必要交互上下文，不提供预期业务答案。盲测结果交回原型 Agent 修改投影，不能直接修改业务事实。

## 反馈事实

操作原型后区分：

- 用户明确确认的功能和结果；
- 仅可观察但未确认业务意义的行为；
- 视觉偏好；
- 原型临时实现；
- 新暴露的业务规则、冲突和未知。

把结果交给主控。业务设计 Agent 决定如何更新 `业务设计.md`；原型自身不能暗中成为新权威。
