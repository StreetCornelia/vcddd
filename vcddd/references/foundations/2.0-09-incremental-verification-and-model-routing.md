# VCDDD 2.0 阶段性成果（九）：面向证据的动态验证与模型选择

> 日期：2026-07-31
> 当前说明：原有固定任务级、阶段级、最终级审核链与模型配置流程已经废弃；运行规则以 `SKILL.md` 和 `instructions/` 为准。

## 1. 验证解决什么问题

代码存在、提交存在和 Agent 报告完成都不能证明结果真实可用。验证需要回答当前交付最可能怎样失败、已有证据能说明什么、哪些真实路径仍未观察到。

实现、自检、测试、审核和集成可以在工作过程中穿插。发现问题后直接修正受影响结果并补充相应证据；不受影响的调查、实现和验证继续。

## 2. 证据跟随实际结论

证据范围由当前结论决定：

- 声称代码可编译，就提供对应构建或静态检查结果；
- 声称模块行为正确，就运行能覆盖该行为及主要失败方式的检查；
- 声称真实外部路径可用，就使用真实入口、环境与可观察结果；
- 声称多个改动组合正确，就在包含这些改动的 baseline 上检查组合行为；
- 暂时缺少环境、账号或依赖时，明确哪些结论尚不能作出，并继续不受影响工作。

Mock、Fake 和 Stub 可以证明对应测试层的逻辑，不能冒充真实接入。证据应定位到实际 baseline、环境、命令或观察结果，并说明未覆盖范围。

## 3. 独立判断按价值使用

独立测试或审核适合补足实现者视角难以发现的具体盲区。主控给独立人物明确 baseline、风险、预期行为和真实入口；独立人物只回答当前问题，不重复研究整个项目，也不控制无关工作的节奏。

## 4. 模型按任务选择

主控根据任务的认知难度、上下文规模、工具能力、成本和可用模型动态选择执行者。并发容量是上限，不是必须占满的目标；边界清楚的小任务可以使用轻量模型，跨事实所有权、重大歧义或不可逆风险需要更强判断。

模型选择不要求项目预先维护固定档位、映射表或确认流程。当前环境缺少用户指定模型时，主控说明限制，使用最接近且适合该小任务的可用模型，或者在差异会实质影响结果时请求用户决定。

## 5. 工具边界

工具可以运行构建、测试、静态检查、环境探测和确定性结构校验。工具结果是判断证据，不替代专业判断，也不因为缺少某份状态文件而阻止能够直接完成的工作。
