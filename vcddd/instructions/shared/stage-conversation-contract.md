# 专业对话合同

**适用身份：** 主控 Agent 与当前阶段的主专业 Agent。这是一份双方边界合同；其中“主控”与“专业 Agent”各自只执行标明属于自己的动作。

## 对话形态

每个需要用户反复参与的大阶段，使用独立、同级、可交互的专业对话。

- 主控负责创建、登记和恢复。
- 专业 Agent 负责直接与用户协作并维护阶段产出。
- 每个实际参与的 Agent 分别维护自己的执行记录，不共写同一份记录。
- 用户不需要通过主控转述每轮专业讨论。

当你是主控且不能创建同级对话时，向用户报告限制。不要静默改成隐藏子 Agent，也不要接管专业工作。

## 生命周期

主控遇到同一工作 ID、同一路线、同一主职责的以下活动时，应恢复原专业对话：

- 继续挖掘；
- 根据用户反馈修正；
- 补齐阶段文档；
- 对阶段结果进行用户确认；
- 主控 AI 按完成合同检查后退回的限定补充。

当你是主控时，只有出现以下情况才新建专业对话：

- 主职责变化；
- 阶段变化；
- 用户要求独立、盲测或隔离判断；
- 原对话已不可恢复；
- 原工作被明确 `superseded`。

## 主写者

当你是主控时，只写自己的执行记录和流程交接，不写阶段结果。

当你是主专业 Agent 时，你是正式阶段结果的唯一主写者。条件 Agent 只向你返回建议或证据，由你决定如何纳入；不要让多个 Agent 并发改写同一权威文档。

当你是条件 Agent 时，只写自己的执行记录和角色合同规定的输出，不修改主专业 Agent 拥有的文档。

## 首轮上下文

当你是专业 Agent 时，首轮只读取：

1. 自己的角色合同；
2. 当前路线的阶段合同；
3. 任务上下文清单中的 `core` 和 `always`；
4. 固定版本的直接权威来源；
5. 将要填写的模板。

首次建立独立判断所需的读取是合理成本，不应为了省 Token 删除必要事实。

## 续轮上下文

当你是主控时，恢复专业对话只补充：

- 用户新增或改变的决定；
- 发生变化的权威文档及其 diff；
- 上轮未完成检查点；
- 本轮明确目标；
- 新触发的 `on-trigger` 上下文。

不要重复发送没有变化的长文档。当你是专业 Agent 且无法确认自己仍持有某条关键事实时，按清单重新读取对应章节。

## 记录边界

无论你是主控、主专业 Agent 还是条件 Agent，都只在自己的执行记录中写：

- 做了什么；
- 使用了哪些来源与版本；
- 产生或更新了什么；
- 用户作了什么决定；
- 当前状态、阻塞和下一步。

执行记录不写：

- 隐式思维链；
- 冗长逐轮复述；
- 未被采用的临时推理过程；
- 与交接和审计无关的工具噪声。

## 结束与交接

当你是专业 Agent 时，必须在用户确认后：

1. 将阶段结果标记为 `confirmed`；
2. 在执行记录中写入确认引用；
3. 完成路线检查点；
4. 写出下一阶段需要接收的输入；
5. 通知用户返回主控对话。

当你是主控时，只以主控身份判断合同记录是否完整一致，不对专业结论做第二次设计。不得把这项判断委托给脚本。
