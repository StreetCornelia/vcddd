# 执行记录合同

**适用身份：** 所有实际参与 VCDDD 工作的 Agent，包括主控、主专业 Agent 和条件 Agent。

## 设计

你与其他角色共用一个执行记录内核，各身份、阶段或路线只扩展检查点。你只维护自己的执行记录，不替其他角色补写。执行记录用于恢复、交接和审计，不是阶段结果本身，也不是逐字聊天记录。

## 稳定内核

你维护的执行记录必须包含：

- 工作、阶段、路线、角色、专业对话 ID；
- 对应结果笔记；
- 本轮目标；
- 启动上下文及固定版本；
- 路线检查点表；
- 关键事件；
- 实际上下文使用；
- 产出与链接；
- 用户确认；
- 当前状态、阻塞和下一步；
- 交接目标。

使用 [统一执行记录模板](../../assets/templates/shared/execution-record-template.md)。

## 检查点扩展

你的身份或路线合同会定义：

- 检查点代码；
- 完成条件；
- 所需证据；
- 是否允许标记不适用。

开始工作时，把属于你的检查点复制到统一模板的检查点表。不要为自己的身份或路线复制整份执行记录模板。

## 更新时机

只在语义节点更新：

- 路线或目标确认；
- 新的一组候选场景形成；
- 用户作出范围决定；
- 权威文档发生实质更新；
- 检查点完成；
- 出现或解除阻塞；
- 用户确认阶段结果；
- 完成交接。

不要在每条消息、每次读取或每个工具调用后更新。

## 上下文使用记录

至少记录：

| 字段 | 内容 |
|---|---|
| 来源 | 文件、章节 ID、页面或证据链接 |
| 固定版本 | Commit、内容哈希或明确快照 |
| 策略 | `core` / `always` / `when-changed` / `on-trigger` |
| 实际读取范围 | 章节、行区间、页面状态或“未读取” |
| 使用原因 | 它支持哪个任务或决定 |

“禁止上下文”只需记录规则和是否遵守，不要为了证明禁止而读取它。

## 完成定义

你必须亲自根据合同、正文与证据判断以下条件，不得交给脚本打分或裁决。主专业 Agent 的执行记录只有同时满足以下条件才能设为 `confirmed`：

- 路线必需检查点完成；
- 阶段结果存在并链接；
- 用户确认内容可定位；
- 未决项和下一步已记录；
- 实际使用的上下文可追溯。

主控和条件 Agent 没有阶段确认权：

- 主控等待专业对话工作时将自己的记录标记为 `waiting`，完成阶段交接后标记为 `completed`；
- 条件 Agent 在输出已按角色合同交回后，将自己的记录标记为 `completed`；
- 它们不得把阶段结果或自己的执行记录标记成用户确认的替代品。
