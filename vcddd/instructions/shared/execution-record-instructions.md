# 执行记录说明

**适用身份：** 所有实际参与 VCDDD 工作的 Agent，包括项目经理、主专业人物和辅助人物。

## 设计

你与其他角色共用同一套轻量记录原则。你只维护自己的执行记录，不替其他角色补写。执行记录是按需使用的恢复、能力衔接和审计工具，不是每个 Agent、角色切换或单次任务都必须创建的专业结果，也不是逐字聊天记录。

## 可选内容

当本次工作需要跨轮恢复、跨能力交接、可审计的持续跟踪，或用户明确要求记录时，可以创建或续用执行记录。只记录本次恢复或交接真正需要的内容：

- 目标；
- 已知事实与相关来源；
- 结果；
- 支持结果的证据；
- 未决项及其影响。

这些内容都是可选项，不要求在开始工作前填齐，也不构成启动、继续、切换能力或交付结果的条件。

需要创建记录时，可以从模板树中的 [执行记录文件](../../assets/templates/vcddd-obsidian/work/<work-id>-<work-name>/执行记录/<role-or-task-name>.md) 取用相关字段。

用户直接调用专业角色时，由该角色按上述条件决定是否创建或续用执行记录。普通、可在单轮完成且不需要长期恢复或交接的任务不创建执行记录，也不因切换角色补建记录。存在执行记录时，只保证其中写下的事实、结果和证据可定位；不要求补造主控状态或其他配套记录。

执行记录存放在 `vcddd-obsidian/work/<work-id>-<work-name>/执行记录/`，只保存在本地，不进入 Git。执行记录可以链接本轮创建或更新的正式事实；正式事实不得反向链接执行记录，也不得保存 `work_id` 或 Agent 对话 ID。

执行记录也不能保存 Key、Token、密码、证书内容、会话凭证或其他敏感值。需要记录真实运行条件时，只写配置名称、安全引用、Provider 或环境、最小权限、使用范围、验证状态和失效状态。工具输出或日志包含敏感值时，先脱敏再记录。

## 更新时机

已有执行记录时，只在语义节点更新：

- 目标或范围改变；
- 新的一组事实或候选形成；
- 用户作出范围决定；
- 权威文档发生实质更新；
- 出现、变化或解除具体限制；
- 结果或证据发生实质变化；
- 新增需要后续处理的未决项。

不要在每条消息、每次读取或每个工具调用后更新。

## 来源与证据

只在结果依赖某项外部事实、特定代码状态或可复现观察时，记录足以定位它的来源、范围和相关版本。版本、Commit 或哈希只在内容变化会影响判断时写入，不要求为每项来源制作快照，也不要求建立完整上下文清单。

“禁止上下文”只需遵守；不要为了证明禁止而读取或登记它。未实际使用的来源不写入执行记录。

结果由当前事实拥有者判断和表述。用户决定直接作为事实记录；项目经理和辅助人物不得用自己的执行记录替代事实拥有者的专业结果或控制其他能力的工作节奏。
