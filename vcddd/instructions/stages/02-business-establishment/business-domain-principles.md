# 业务与 Domain 判断规则

**适用身份：** 使用业务定义、Domain 发现、Domain 建模或业务组合能力的业务 Leader。

## 业务是什么

业务说明现实中的参与者希望完成什么事情：在什么情况下，依据什么事实和关系，谁作出什么决定或执行什么行动，使什么人、事或物发生变化，并产生什么可观察结果。

业务可以跨越多个 Domain。业务动作、功能、页面、用例和流程步骤都不能直接证明存在同名 Domain。

## Domain 是什么

Domain 是业务世界中一个能够自治、自洽的核心事物。判断候选时必须回答：

- 它在现实业务中是什么；
- 它自己拥有什么信息、状态和关系；
- 它维护怎样的生命周期和不变量；
- 它能依据自身事实作出什么判断；
- 它能执行或承受什么行为；
- 行为使自身发生什么变化；
- 它会对外产生什么事实或影响；
- 哪些事实和行为明确不归它拥有。

自治表示 Domain 对自己承担的判断拥有最终解释权；自洽表示它能够用自己拥有的事实、关系和规则解释行为及结果。外部组合可以触发 Domain、提供外部事实和传递结果，不能取出它的数据后替它完成业务判断。

## 找出 Domain

不得从以下对象直接创建 Domain：

- User Story 或功能名称；
- 页面、按钮和报表；
- 流程步骤、批处理和技术任务；
- Controller、Service、Repository、模块或数据表；
- 为协调多个调用而创造的抽象“处理、编排、管理、能力”。

多个 Domain 参与一项业务时，先判断现实中是否真的存在一个更高层的业务之“事”。只有它拥有自身身份、状态、规则、成功失败、恢复和结果时，才把它作为 Domain 候选；否则保持为应用组合。

## 业务组合

业务组合负责连接已经属于各 Domain 的行为和结果：

```text
业务意图
→ Domain A 依据自己拥有的事实作出判断并产生结果
→ 组合层传递必要结果
→ Domain B 完成属于自己的行为并产生影响
→ 形成参与者可观察的业务结果
```

组合关系不能获得新的业务主权。缺少决定拥有者时，返回业务定义或 Domain 发现能力；某个 Domain 行为不足时，返回该 Domain 的 Domain 建模能力负责人。

## Pre-Coding 投影边界

业务定义、领域地图、Domain 文档和业务组合是本能力的事实。架构、模块、API、逐 API 编排、数据库和开发基线是这些事实面向 Coding 的切面投影，由 Pre-Coding 角色形成。

本能力可以记录某个业务结果需要被调用、保存或观察，但不得提前确定协议、表结构、代码模块和实现机制。

## 用户与 AI 的责任

AI 主动调查、提出完整认识、寻找反例并推荐方案。用户决定现实业务目标、事实所有权、关系、行为归属以及 Domain 是否正确表达业务世界。用户确认的是确切产出的当前版本，不是对后续投影或实现的预先授权。
