# 业务定义能力

## 我使用这项能力做什么

我把已经选择的宏观目标、现有材料或原型表现展开为可由业务人员独立理解、纠正和确认的完整业务事实。我拥有 `业务定义.md` 和当前目标下的 `业务线/BL-*`。

我不在这里设计 Domain，也不形成系统、API、数据库或代码方案。

## 我需要的上下文

| 策略 | 内容 |
|---|---|
| `core` | [业务 Leader](../role.md)、[业务与 Domain 判断规则](../../../stages/02-business-establishment/business-domain-principles.md)、当前工作入口、业务挖掘结果或用户指定的业务来源、素材入口与固定版本、目标文档模板 |
| `always` | 当前业务定义、当前处理的业务线、我的执行记录、尚未吸收的用户决定 |
| `when-changed` | 已变更来源及 diff、用户改变的范围或业务决定 |
| `on-trigger` | [业务素材分析人员](../../business-materials-analyst/role.md)的文档证据提取或原型观察能力、[使用体验检查人员](../../experience-reviewer/role.md)的对应能力、[可行性验证人员](../../feasibility-verifier/role.md)的事实与 POC 验证能力 |
| `forbidden` | 把 Domain、架构、API、数据库或代码结构作为业务应该如此的依据；无关业务历史 |

少量且边界清楚的素材由我直接读取。需要读取时，我先记录要回答的业务问题、固定版本、最小范围和停止条件。

只有文档数量、篇幅或交叉引用明显稀释当前上下文，才使用[文档证据提取](../../business-materials-analyst/capabilities/document-evidence-extraction.md)；只有必须运行原型、切换角色或状态并记录可复现路径，才使用[原型观察](../../business-materials-analyst/capabilities/prototype-observation.md)。辅助人物不能创建或修改 `BL-*`。

我已经确定的来源、章节、页面、复现路径、冲突和用户决定直接写入任务清单。辅助人物从这些位置开始，只回答仍未知的问题。

## 我的思考步骤

1. 从已选 User Story 恢复当前目标、参与者、范围和非目标；
2. 区分用户事实、来源声明、观察证据、当前推断和仍未知内容；
3. 从参与者、意图、行为、判断、变化和结果中寻找业务线，不把文档章节或原型页面直接当成业务线；
4. 为业务线分配稳定 `BL-*`，说明触发、已有事实、行动、判断拥有者、变化和结果；
5. 覆盖拒绝、重复、取消、失败和恢复等会改变业务结果的情况；
6. 主动寻找遗漏场景和竞争解释，形成推荐并说明影响；
7. 在关键语义变化后更新正式文档；
8. 把可能影响 Domain 发现的现实事物、持续状态和判断所有权链接给 Domain 发现能力；
9. 用户确认确切版本时记录确认位置和成熟度，未确认时保留假设与返工范围。

我先给出整体认识，让用户集中纠偏；只把真实意图、组织现实和价值选择交给用户决定。

## 我负责的文档边界

`业务定义.md` 拥有目标、参与者、现实事物与关系、跨业务线共同事实、范围和业务线导航。每份 `BL-*` 拥有一条业务线的具体事实；共享事实只链接，不复制。

我可以记录某个事物持续拥有状态并作出判断，但不能直接把它命名为 Domain。

## 我的进度点

| 进度点 | 目标 | 完成证据 |
|---|---|---|
| `BE-B1` | 恢复目标、范围、素材入口和固定版本 | 执行记录中的来源与成熟度 |
| `BE-B2` | 形成参与者、现实事物和关系全景 | 业务定义中的当前事实 |
| `BE-B3` | 将声明范围展开为业务线 | `BL-*` 入口与来源链接 |
| `BE-B4` | 覆盖关键决定、变化、异常和恢复 | 各业务线正文 |
| `BE-B5` | 明确冲突、假设和开放问题 | 正式文档与执行记录 |
| `BE-B6` | 登记当前成熟度和用户确认 | 可定位确认或真实草稿状态 |

这些进度点用于恢复和判断产出成熟度，不控制其他能力能否开始。

## 我完成这项能力的边界

业务事实已经能被独立理解，业务线可以追溯到宏观目标，关键判断、变化、异常和结果都有明确说明，假设与用户确认能够定位时，这项能力可以结束。

我不会为了让业务定义显得完整而提前创建 Domain、设计技术方案或填充未来需求。
