# 表达盲测能力

## 我使用这项能力做什么

我在不知道设计答案的条件下，验证一个名称或短文案在实际场景中会被目标使用者理解成什么，是否产生会导致错误判断或操作的歧义。

## 使用条件

- AI 新创造的重要业务或 Domain 名称准备跨人物使用；
- 业务确认文案可能使用户误解对象、范围或影响；
- 网页标题、操作文案或提示用于发现或确认业务；
- 用户明确怀疑当前表达含义不清。

用户已经持续使用且没有歧义的名称不机械盲测。一般希望获得第二意见也不能单独触发。

## 我需要的输入

- 表达场景；
- 目标使用者和合理背景；
- 实际出现位置；
- 同时可见的上下文；
- 原始名称或文案；
- 这一层表达应承担的责任；
- 输入快照；
- 允许和禁止读取的内容。

我可以读取真实展示、必要截图和同屏或同章节上下文。禁止读取预期正确含义、原作者命名理由、专门解释答案的章节、用户对正确答案的反馈和以前的盲测结果。

已知的展示位置和真实上下文必须直接提供；隔离的是答案和推理，不是让盲测者重新寻找被测对象。

## 按场景判断

| 场景 | 必须表达 | 不必塞进名称或短文案 |
|---|---|---|
| Domain | 指向哪个稳定核心事物 | 全部属性、行为、规则和失败分支 |
| 业务设计 | 结合章节能理解具体的人、事、关系、动作或结果 | 脱离全文解释全部业务 |
| 业务确认 | 知道确认对象、范围和重要影响 | 把完整设计压进标题或按钮 |
| 网页标题 | 知道当前页面处理什么 | 重复页面已经展示的全部信息 |
| 网页操作 | 结合页面知道动作和主要结果 | 在按钮写完前提、过程和所有后果 |
| Domain 行为 | 知道哪个 Domain 做什么并产生什么主要结果 | 重复主体定义和全部异常 |

## 最小充分判断

我依次判断实际理解、是否足以完成当前动作、是否存在实质歧义、缺失信息应由名称还是上下文承担、最小修改是什么，以及修改是否让名称承担了不属于它的责任。

结果只能是：

- `clear-in-context`；
- `ambiguous-in-context`；
- `cannot-understand-in-context`；
- `contaminated`。

这些状态只说明表达效果，不说明业务或 Domain 正确。

## 独立性和复测

我把结果交回事实拥有者。修改后的复测必须使用新的 Agent，只提供修改后的实际展示内容；已经知道答案的原 Agent 不再具有盲测价值。

## 我的进度点

| 进度点 | 目标 | 完成证据 |
|---|---|---|
| `EXP-B1` | 固定场景、使用者和实际上下文 | 输入快照 |
| `EXP-B2` | 保持答案隔离 | 禁止上下文与读取记录 |
| `EXP-B3` | 完成实际理解与歧义测试 | 逐项理解结果 |
| `EXP-B4` | 判断信息应由名称还是上下文承担 | 最小充分建议 |
| `EXP-B5` | 把结果交回事实拥有者 | 结果链接与接收人物 |
