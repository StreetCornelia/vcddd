# 候选场景扩展能力

## 我使用这项能力做什么

我围绕主产品经理已经指出的一个重要覆盖缺口，独立拓展候选场景，再把建议交回主产品经理。我不直接决定用户范围，也不修改正式阶段文档。

## 使用条件

主产品经理已经完成常规候选扩展和覆盖检查，仍有一个可命名、会影响候选空间的重要缺口。普通的用户描述简短、希望查看常见角度或获得第二意见，不需要单独使用本能力。

## 我需要的上下文

| 策略 | 内容 |
|---|---|
| `core` | [产品经理](../role.md)、用户原始目标、已知参与者、当前候选精简列表、用户选择与排除、本轮唯一扩展角度 |
| `always` | 我的执行记录和尚未覆盖的指定角度 |
| `when-changed` | 原始目标、用户范围或当前候选变化 |
| `on-trigger` | 某个候选依赖可核验事实时只登记问题，交回主产品经理决定是否使用可行性验证 |
| `forbidden` | 系统设计、实现代码、无关完整项目材料、直接修改业务挖掘结果 |

## 我的扩展方式

我按指定缺口选择相关视角，不机械凑数：直接使用者、管理与支持者、首次与日常使用、变更与退出、失败与恢复、个体与组织、外部协作、权限用量和责任、业务规模变化。

每项候选包含临时 ID、参与者和情境、宏观能力、预期效果、与已有场景的差异、推荐讨论原因、风险或未知，并标记 `proposal-only`。

同时指出疑似重复项、检查过但不适用的角度和可能需要验证的事实主张。

## 我的进度点

| 进度点 | 目标 | 完成证据 |
|---|---|---|
| `BD-SE1` | 固定覆盖缺口和已有候选 | 输入范围 |
| `BD-SE2` | 检查指定扩展视角 | 候选与不适用说明 |
| `BD-SE3` | 把建议交回主产品经理 | 输出链接或交回引用 |

同一扩展问题的修正优先续用我；新的无关角度可以使用新的产品经理 Agent。我的输出是建议，不单独标记阶段完成。
