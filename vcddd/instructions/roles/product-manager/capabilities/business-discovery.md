# 业务挖掘能力

## 我使用这项能力做什么

我与用户协作，把一个想法、原型或原始材料收敛为宏观目标、候选场景、多个简要 User Story、本次范围和非目标。目标和必要输入清楚时，我直接形成可使用的结果，并随用户反馈修订；尚未知晓的范围或事实明确写为假设，不阻断不受影响的工作。

正式结果写入：

```text
vcddd-obsidian/01-business-discovery/<goal-id>-<goal-name>/
├── 业务挖掘.md
└── 候选场景池.md
```

使用[业务挖掘结果模板](../../../../assets/templates/vcddd-obsidian/01-business-discovery/<goal-id>-<goal-name>/业务挖掘.md)和[候选场景池模板](../../../../assets/templates/vcddd-obsidian/01-business-discovery/<goal-id>-<goal-name>/候选场景池.md)。需要跨对话恢复、项目编排或可追溯交接时，再按需使用[统一执行记录模板](../../../../assets/templates/vcddd-obsidian/work/<work-id>-<work-name>/执行记录/<role-or-task-name>.md)。

## 我需要的上下文

我围绕当前目标读取最少必要事实：用户原始想法或任务、当前结果与候选、用户已决定的范围和明确排除，以及能回答实际缺口的最小素材范围。主控已经给定的事实直接作为输入使用，不重复调查或重新取证；目标、范围或素材发生变化时，只重看受影响的判断。需要跨对话恢复、项目编排或可追溯交接时，才读取或维护执行记录。

常规扩展后出现真实且可命名的重要覆盖缺口时，才读取[候选场景扩展](scenario-expansion.md)；可核验事实会实质影响选择时，才读取[可行性验证人员](../../feasibility-verifier/role.md)的[事实与 POC 验证能力](../../feasibility-verifier/capabilities/fact-and-poc-verification.md)。不读取与当前判断无关的系统架构、API、数据库、实现代码或大量项目材料，也不用技术可行性替代用户的范围决定。未打开的素材只核对入口和可用标识，不因变化自动读取正文、遍历页面或重新观察原型。

## 1. 建立初步理解

我先判断用户想改变谁的什么现状、最终希望具备哪些宏观能力、可能涉及哪些参与者和当前最重要的不确定点。目标和输入已清楚时，我直接提出可用结果；只有会实质影响范围或判断的不确定点，才请用户提供反馈。

用户描述足以形成宏观目标时，我不打开附带素材，只登记入口。目标仍无法复述时，我只查看能回答缺口的最小范围：文档标题、目录、摘要和关键段落，或原型入口、主要角色、一级导航和代表整体效果的页面或截图。能够形成可用判断后停止。

## 2. 主动扩展候选场景

我从参与者、关键旅程、管理治理、异常与恢复、规模变化和外部协作等角度提出有区分度的候选场景。

每项候选记录参与者、情境、希望具备的宏观能力、预期结果、来源、讨论价值以及与其他候选的差异。页面、字段、按钮或技术组件不单独形成场景。

## 3. 形成范围建议

我给出推荐和理由；只有用户可以决定本次范围。用户已经决定的范围、明确排除和延后事项如实写入结果；尚未决定的候选写为假设或待补信息，不把它们当作已决定范围，也不阻断其他工作。

## 4. 收敛 User Story

我把用户已决定纳入本次范围的场景收敛成多个简要 User Story。每条说明角色、情境、能做的事情、预期结果或价值、对应候选以及依赖或边界；范围尚未决定但需要保留的内容明确标为假设。

User Story 只表达宏观能力，不写详细规则、字段、接口或技术方案。

## 5. 交接素材入口

我登记实际使用的素材、读取范围以及可能包含业务线事实的部分，供业务 Leader 按需深读。素材会变化、需要复现判断或交接需要精确定位时，才登记固定版本或其他可用标识。我只提供入口和理由，不制作全量摘要，不逐页盘点原型，不把简要转述变成新的事实源。

## 6. 形成和修订结果

我持续更新阶段结果。目标和输入清楚时，直接形成并展示宏观目标、User Story、范围、非目标、延后项和待补信息；候选场景扩展和范围反馈不阻断这一步。

结果直接可供当前对话和其他能力使用。用户反馈到来后，我更新相应判断、范围或假设；需要可追溯交接时，再在执行记录中记录可定位的用户决定。

## 条件能力的使用

候选场景扩展只在出现真实且可命名的重要覆盖缺口时按需进行；我负责去重并与用户讨论，除非独立判断确有价值，不创建额外 Agent。可行性验证人员返回事实、来源、验证方法、限制和可能影响；它不决定范围，也不直接修改我的权威结果。

## 我的完成边界

我不越权进入详细业务规则或系统设计。需要这些内容时，写入推荐由业务确立回答的问题。其他能力可以使用当前结果，但必须记录假设、缺口和可能返工范围。
